FLOR DE LISTA — CONFIGURAÇÃO

O README apresenta somente o projeto e sua ideia. As instruções práticas estão aqui.

1. Crie um NOVO projeto em https://console.firebase.google.com/
   Nome: Flor de Lista. Sugestão de ID: flor-de-lista-glauco (depende de disponibilidade).
2. Em Authentication, habilite o provedor E-mail/senha.
3. Em Firestore Database, crie o banco (default), edição Standard, modo de produção.
4. Na aba Regras do Firestore, substitua o conteúdo pelo arquivo firestore.rules desta pasta e publique.
5. Em Configurações > Geral > Seus aplicativos, registre um app Web com apelido flor-de-lista-web.
6. Copie apiKey, authDomain, projectId e appId para public/firebase-config.js. Mantenha export const firebaseConfig.
7. Salve o arquivo e atualize o site.

Os módulos Firebase já são importados via CDN. Não precisa executar npm install firebase.
A configuração Web é pública. Não inclua senhas ou chaves privadas no código.

EXECUTAR:
Abra public/index.html no VS Code e use Ctrl+Shift+P > Live Server: Open with Live Server.
Ou, com Python instalado, execute no PowerShell:
cd "C:\Users\ronal\Desktop\Projetos Glauco\flor-de-lista"
py -m http.server 5504 --bind 127.0.0.1 --directory public
Abra http://localhost:5504/. Se essa porta estiver ocupada, escolha outra no comando e no endereço.
O site precisa de internet e deve ser aberto por http://, não por file://.

ONDE FICAM OS DADOS:
As contas aparecem em Authentication > Usuários.
As tarefas ficam em users/UID_DA_CONTA/tasks/ID_DA_TAREFA.
A primeira tarefa cria a estrutura automaticamente; não precisa criar tabela manualmente.
Cada usuário só pode ler e modificar suas próprias tarefas. O documento do usuário pode aparecer em itálico por só conter uma subcoleção.

PUBLICAÇÃO OPCIONAL COM FIREBASE HOSTING:
npm install -g firebase-tools
firebase login
firebase deploy --only hosting,firestore:rules --project SEU_ID_REAL
Substitua SEU_ID_REAL pelo ID do projeto novo. firebase.json já está preparado.

EVIDÊNCIAS:
Depois de conectar seu Firebase, grave cadastro, saída, login, criação, edição, conclusão e exclusão de uma tarefa.
Mostre as alterações no site e no console Firestore. Use dados fictícios.
As imagens em previas são testes locais com emuladores, não comprovam publicação no Firebase real.

PROBLEMAS:
Acesso negado: confira o ID do projeto e publique firestore.rules.
Domínio não autorizado: adicione localhost ou 127.0.0.1 nos domínios autorizados do Authentication, sem porta.
Login indisponível: confira se E-mail/senha foi habilitado.
Os logins dos outros sites não são copiados para o novo projeto.
